# OrientMark result transfer
[English](README.md) | [Русский](README.ru.md)

Репозиторий: [orient-mark/result-transfer](https://github.com/orient-mark/result-transfer).
Ветка разработки: `dev`. Лицензия: [MIT](LICENSE).

Общий пакет на чистом Dart для приложений OrientMark `sportsman` и `event-organizer`. Определяет формат результата участника, разбивает его на пакеты и собирает полученные пакеты с проверкой целостности. Отрисовка QR, анимация, работа камеры и сохранение файлов реализованы в приложениях.

## Подключение
Добавьте Git-зависимость в `pubspec.yaml` приложения:

```yaml
dependencies:
  result_transfer:
    git:
      url: https://github.com/orient-mark/result-transfer.git
      ref: dev
```

Загрузите зависимости:

```bash
flutter pub get
```

Импортируйте пакет:

```dart
import 'package:result_transfer/result_transfer.dart';
```

Требуется Dart SDK `^3.13.0`. Пакет распространяется через Git и не опубликован на pub.dev.

## Передача
Используется последовательная передача пакетов через анимированный QR. Кадры повторяются по кругу: пропущенный пакет можно считать на следующем круге. Этот формат не использует BC-UR или fountain-кодирование.

Для обмена не нужны сеть и канал обратного подтверждения. Успешный приём подтверждается только на телефоне организатора. Телефон спортсмена продолжает показ кадров, пока пользователь не закроет экран передачи.

## Файл результата
Результат передаётся в JSON с кодировкой UTF-8:

```json
{
  "format": "orientmark-result",
  "version": 0,
  "name": "Alex",
  "surname": "Smith",
  "number_chip": 42,
  "start": null,
  "finish": "2026-10-01T09:30:00.000Z",
  "count_cp": 2,
  "marks": [
    { "code": "31", "time": "2026-10-01T09:10:00.000Z" },
    { "code": "32", "time": "2026-10-01T09:20:00.000Z" }
  ]
}
```

| Поле | Описание |
| --- | --- |
| `format` | Идентификатор формата документа. Для результата OrientMark — `"orientmark-result"`. |
| `version` | `1` — с регистрационной идентификацией; `0` — прежний документ. Версия оболочки QR-пакетов остаётся 0. |
| `participant_id` | UUIDv5 общей библиотеки идентификации, обязателен в v1. |
| `patronymic` | Отчество или пустая строка, обязательно в v1. |
| `birth_date` | Полная дата рождения в формате дд.мм.гггг, обязательна в v1. |
| `name` | Имя участника. |
| `surname` | Фамилия участника. |
| `number_chip` | Номер чипа участника, целое число. |
| `start` | Время отметки старта; при отсутствии отметки — `null`. Если отметка есть, например: `"2026-10-01T09:00:00.000Z"`. |
| `finish` | Время финиша; `null`, если попытка не завершена. |
| `count_cp` | Количество отметок КП. Должно совпадать с длиной `marks`; без отметок — `0`. |
| `marks` | Массив отметок в сохранённом порядке. Без отметок — `[]`. |
| `marks[].code` | Код КП, строка. |
| `marks[].time` | Абсолютное время отметки КП. |

Все значения времени записываются в ISO-8601 UTC; суффикс `Z` обозначает UTC. Порядок и повторные посещения сохраняются. Пакет не проверяет правильность прохождения дистанции. Результат без отметок КП и без отметки старта допустим. `ResultDocument` — неизменяемая копия результата, не ссылка на изменяемый сплит в хранилище приложения спортсмена.

Документ v1 создаётся при наличии `participantId`. Перед записью результата в БД организатор сверяет UUID с ФИО/ДР по общей библиотеке. Старые документы можно собрать из пакетов, но без UUID они не принимаются в мероприятие. В пакете 2.0.0 изменён API: `ResultDocument.finish` допускает `null`. Для работы нужно обновить оба приложения.

## QR-кадр
Каждый QR-кадр передаёт один пакет в формате JSON. В примере ниже результат из предыдущего раздела записан без пробелов и переносов строк и помещается в один пакет:

```json
{
  "qr": "orientmark",
  "v": 0,
  "id": "9981a7beb9622bc86110afb33735b6e0a9a199d1fd823c1212c0c240c63a982e",
  "index": 0,
  "total": 1,
  "bytes": 259,
  "hash": "9981a7beb9622bc86110afb33735b6e0a9a199d1fd823c1212c0c240c63a982e",
  "data": "eyJmb3JtYXQiOiJvcmllbnRtYXJrLXJlc3VsdCIsInZlcnNpb24iOjAsIm5hbWUiOiJBbGV4Iiwic3VybmFtZSI6IlNtaXRoIiwibnVtYmVyX2NoaXAiOjQyLCJzdGFydCI6bnVsbCwiZmluaXNoIjoiMjAyNi0xMC0wMVQwOTozMDowMC4wMDBaIiwiY291bnRfY3AiOjIsIm1hcmtzIjpbeyJjb2RlIjoiMzEiLCJ0aW1lIjoiMjAyNi0xMC0wMVQwOToxMDowMC4wMDBaIn0seyJjb2RlIjoiMzIiLCJ0aW1lIjoiMjAyNi0xMC0wMVQwOToyMDowMC4wMDBaIn1dfQ=="
}
```

| Поле | Описание |
| --- | --- |
| `qr` | Идентификатор протокола: `"orientmark"`. |
| `v` | Версия протокола пакетов, сейчас — `0`; задаётся отдельно от версии документа результата (`version`). |
| `id` | Идентификатор передачи: SHA-256 всего файла результата в UTF-8. Одинаков для всех пакетов передачи. |
| `index` | Номер пакета, начиная с `0`. |
| `total` | Общее количество пакетов, необходимых для сборки результата. |
| `bytes` | Размер всего файла результата в байтах до кодирования в base64. |
| `hash` | SHA-256 байтов этого пакета до кодирования в base64. |
| `data` | Байты пакета, закодированные в строку base64. |

В этом примере `total` равен `1`, а `bytes` — `259`. Значения `id` и `hash` совпадают, поскольку единственный пакет содержит весь файл.

Файл делится по байтам, после чего каждый пакет кодируется в base64. UTF-8 декодируется только после сборки: граница пакета может проходить внутри многобайтного символа, например кириллической буквы.

Размер пакета — 360 байт, кроме последнего. Ограничения: 1024 пакета, 368 640 байт на файл и 1024 символа в строке QR-кадра. Сборщик проверяет параметры и контрольную сумму пакета перед его сохранением в памяти, а перед выдачей результата — контрольную сумму всего файла и структуру документа. Контрольные суммы обнаруживают повреждение данных, но не подтверждают подлинность отправителя.

Пакеты принимаются в любом порядке, повторы игнорируются. Пакеты с другим идентификатором передачи игнорируются до сброса сборки. Неполная передача не выдаёт результат. Ошибка проверки собранного файла сбрасывает сборку, после чего результат можно считать заново.

**Будущие версии протокола не будут поддерживать этот формат.** Отправитель и получатель должны использовать совместимые версии протокола.

## Физическое тестирование
Проверьте полный обмен на двух реальных устройствах:

1. Начните передачу результата из отправляющего приложения, например приложения спортсмена.
2. Запустите приём QR-пакетов в принимающем приложении на втором устройстве.
3. Удерживайте QR в поле зрения камеры до получения полного результата.
4. Сравните полученные данные участника, время и отметки с исходным результатом.

Проверьте финиш без отметок КП, длинный сплит, прерывание и возобновление передачи, пропуск кадров, повторные пакеты, другого участника после сброса приёма и отказ в разрешении на камеру. Оцените скорость считывания при разной частоте кадров и разном освещении.

Скорость и надёжность физической передачи на устройствах пока не проверены.
